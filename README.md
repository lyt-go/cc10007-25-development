# 智能运营决策分析平台

面向用户行为序列分析、RFM分层、流失预警、智能推荐、归因建模、活动效果评估与实时运营决策的数据分析工程平台。

这是一个前后端分离的管理平台：前端 React + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 React + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。

## 数据漂移驱动的评分卡复验（核验码 258e94b9）

供新能力链路把“漂移检测监控数据集 + 评分卡特征记录”推送到后端后，按新链路读取
同一监控数据集并基于 PSI（群体稳定性指数）计算特征偏移与评分稳定性，首次生成
**评分卡复验明细数据集**，并按**处理批次**归档。

### 阈值口径

| 指标 | 阈值 | 超过阈值的结论 |
| --- | --- | --- |
| 单特征 PSI（特征偏移） | 0.10 | 偏移预警，触发漂移告警；≥0.25 为显著漂移 |
| 评分 PSI（评分稳定性） | 0.10 | 评分不稳定，不得保持“稳定”结论 |

漂移告警与评分稳定性一并落库；任一指标超过阈值，数据集都不能继续保持稳定结论。

### 关键规则

- **两个可用基线两套判断**：同一监控数据集同时存在“固定观察窗口”和“最近完整批次”
  两个可用基线时会得到两套漂移判断；评分卡只能引用一个当前基线，按
  “固定观察窗口优先、最近完整批次其次”确定（`MSET-M01` 即该场景）。
- **检测中/失败数据集不可引用**：仍在检测中的数据集（`MSET-M02`）和接收校验失败的
  数据集（`MSET-M03`）都不能作为评分卡当前依据；失败可修正特征记录后重试。
- **唯一可用结果**：结果提交只接收“含评分卡复验明细数据集”的结果，重复提交幂等。
- **批次可追溯**：每条复验明细都带处理批次号；新增数据漂移驱动的复验可从数据批次追溯。
- **结论同步**：评分卡 `SCOR-0003` 当前基线下的告警与稳定性结论同步到数据漂移清单。

### 接口（前缀 `/api/revalidation`）

| 方法与路径 | 说明 |
| --- | --- |
| `GET /datasets` | 数据漂移待处理明细：监控数据集清单 |
| `GET /datasets/{id}` | 数据集详情（基线版本、处理批次、复验明细、当前基线） |
| `POST /datasets` | 新链路接收监控数据集与评分卡特征记录（校验失败可重试） |
| `POST /datasets/{id}/retry` | 失败重试，可携带修正后的特征记录 |
| `POST /datasets/{id}/revalidate` | 执行阈值复验，生成明细并按批次归档 |
| `POST /datasets/{id}/submit` | 提交唯一可用结果（幂等） |
| `GET /details` | 评分卡复验明细数据集（支持 `dataset`、`scorecard`、`current_only`） |
| `GET /batches` | 处理批次归档信息 |
| `GET /baselines` | 同监控数据集的基线版本清单 |
| `GET /current-baseline?dataset=` | 当前基线（检测中/失败数据集返回不可用说明） |
| `GET /contract/scor-0003` | SCOR-0003 契约验证样本：阈值、基线版本、特征偏移、评分稳定性 |
